# Винная подборка — HW3 MMDA

Приложение загружает обученный пайплайн StandardScaler + LogisticRegression.
Модель не обучается внутри Streamlit. Рабочий порог выбран на валидационной
части train: максимум precision при recall ≥ 0.7. Полные дубликаты удалены до
разбиения; тест используется только для оценки.

## Локальный запуск

Python **3.14.8**. Из папки `wine_app`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Для Linux/macOS замените `.\.venv\Scripts\python.exe` на `.venv/bin/python`.
Запуск из корня домашнего задания в уже подготовленном окружении:

```powershell
.\.venv\Scripts\python.exe -m streamlit run wine_app/app.py
```

Рядом с `app.py` должны лежать `model.joblib`, `config.json` и `test.csv`.
Они создаются ячейкой «Сохранение модели» в ноутбуке. Для воспроизведения
всего исследования установите корневой `requirements.txt` и выполните
`HW3_MMDA.ipynb` сверху вниз; рабочая папка — папка ноутбука.

## Возможности

- Одно вино: 12 признаков, вероятность и решение при общем пороге.
- Модельные метрики: матрица ошибок, precision, recall, F1, ROC и PR с рабочими точками.
- Пакетное предсказание: CSV, проверка столбцов и чисел, скачивание результата.
- Коэффициенты: отсортированные веса стандартизированных признаков.

Обязательные столбцы входного CSV:
`fixed_acidity, volatile_acidity, citric_acid, residual_sugar, chlorides,
free_sulfur_dioxide, total_sulfur_dioxide, density, pH, sulphates, alcohol, is_red`.
`is_red`: 0 — белое, 1 — красное. Разделитель — запятая, десятичный знак — точка.
Порядок столбцов не важен. Дополнительные столбцы сохраняются в результате.

## Кэширование (4.5)

`st.cache_resource` хранит один общий объект модели между перезапусками скрипта
и пользовательскими сессиями; приложение только читает его, не переобучает.
`st.cache_data` подходит для таблиц и массивов: сериализует результаты и возвращает
копии, защищая кэш от случайных изменений. Таблица теста и его вероятности
кэшируются отдельно. Аргумент `_model` не хешируется, а `X` входит в ключ кэша.
При замене артефакта модели нужно перезапустить сервер или очистить кэш.

Без декоратора `joblib.load` заново читал бы модель с диска при каждом изменении
виджета. При движении порога тестовые вероятности берутся из кэша; повторяется
сравнение с порогом и расчёт метрик. Вероятность отдельного введённого вина
вычисляется отдельно от тестовых вероятностей.

Источник: [документация кэширования Streamlit](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.cache_resource).

## Публикация в Streamlit Community Cloud (4.6)

Публичный деплой пока **не выполнен**: необходимы аккаунт и GitHub-репозиторий.

1. Добавьте папку `wine_app` со всеми артефактами в свой GitHub-репозиторий.
2. Откройте [Streamlit Community Cloud](https://share.streamlit.io/) и создайте приложение.
3. Укажите репозиторий, ветку и путь `wine_app/app.py`.
4. В Advanced settings выберите Python 3.14, затем запустите деплой.
5. Проверьте все вкладки и вставьте полученную ссылку в последнюю ячейку ноутбука.

[Официальная инструкция по деплою](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy).

## Данные

[Wine Quality, UCI](https://archive.ics.uci.edu/dataset/186/wine+quality),
P. Cortez et al., 2009, CC BY 4.0. Исходный учебный CSV расположен в
`Data/wine_quality.csv`; target = 1 для экспертной оценки не ниже 7.
Модель демонстрационная. Коэффициенты описывают ассоциации, а не причинные эффекты.
